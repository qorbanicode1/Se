# سیستم مدیریت کتابخانه دانشگاه

پروژه‌ی درس مهندسی نرم‌افزار — پیاده‌سازی سیستم مدیریت کتابخانه دانشگاه در **دو نسخه‌ی کامل و هم‌رفتار**:

| نسخه | زبان | دیتابیس | وابستگی |
|------|------|----------|----------|
| اصلی | **Python** | SQLite | هیچ‌کدام (فقط کتابخانه‌ی استاندارد) |
| معادل | **Java** (JDK 8 یا بالاتر) | SQLite از طریق JDBC | درایور `sqlite-jdbc` |

هر دو نسخه اسکیمای یکسان، همان قواعد کسب‌وکار، همان متن منوها و همان فایل `library.db` را دارند؛ یعنی می‌توانید با نسخه‌ی پایتون داده بسازید و با نسخه‌ی جاوا وارد شوید. رمزها هم با PBKDF2-HMAC-SHA256 و قالب `salt:digest` یکسان هش می‌شوند، پس حساب‌ها بین دو نسخه قابل استفاده‌اند.

## ساختار پروژه

| مسیر | توضیح |
|------|-------|
| `main.py` | رابط کاربری خط فرمان (منوهای دانشجو / کارمند / مدیر / مهمان) |
| `services.py` | منطق کسب‌وکار و تمام قواعد سیستم |
| `database.py` | ساخت دیتابیس، جداول و حساب پیش‌فرض مدیر |
| `auth.py` | هش کردن رمز عبور (PBKDF2-HMAC-SHA256) |
| `seed_data.py` | پرکردن دیتابیس با داده‌ی نمونه‌ی تصادفی |
| `smoke_test.py` | تست سرتاسری روی یک دیتابیس موقت |
| `java/src/library/` | نسخه‌ی جاوا — کلاسی به کلاس معادل فایل‌های بالا |
| `java/lib/` | درایور SQLite (`sqlite-jdbc`)؛ در اولین `build.cmd` خودکار دانلود می‌شود |
| `java/build.cmd` / `run.cmd` / `seed.cmd` / `test.cmd` | ساخت و اجرای نسخه‌ی جاوا در ویندوز |

نگاشت کلاس‌های جاوا به پایتون:

| پایتون | جاوا |
|--------|------|
| `main.py` | `App.java` + `Console.java` |
| `services.py` | `Services.java` |
| `database.py` | `Db.java` |
| `auth.py` | `Auth.java` |
| `seed_data.py` | `SeedData.java` |
| `smoke_test.py` | `SmokeTest.java` |
| جدول‌های `users` / `books` / `loans` | `User.java` / `Book.java` / `Loan.java` |

## نحوه‌ی اجرا

### نسخه‌ی پایتون

```bash
python main.py
```

### نسخه‌ی جاوا

```bat
cd java
build.cmd
run.cmd
```

`build.cmd` پروژه را در `java/out` کامپایل می‌کند (اگر درایور موجود نباشد، خودش از Maven Central دانلودش می‌کند) و `run.cmd` برنامه را با دیتابیس مشترک ریشه‌ی پروژه اجرا می‌کند.

اجرای دستی:

```bash
# Linux / macOS
cd java
javac -encoding UTF-8 -d out -cp "lib/sqlite-jdbc-3.42.0.0.jar" src/library/*.java
java -cp "out:lib/sqlite-jdbc-3.42.0.0.jar" library.App
```

```bat
:: Windows (javac خودش wildcard را باز نمی‌کند، از build.cmd استفاده کنید)
cd java
build.cmd
java -cp "out;lib\sqlite-jdbc-3.42.0.0.jar" library.App
```

حساب پیش‌فرض مدیر کتابخانه (در اولین اجرا ساخته می‌شود):

- نام کاربری: `admin`
- رمز عبور: `admin123`

دیتابیس در فایل `library.db` در ریشه‌ی پروژه ساخته می‌شود.

## داده‌ی نمونه و تست

```bash
# پایتون
python seed_data.py
python smoke_test.py
```

```bat
:: جاوا
cd java
seed.cmd
test.cmd
```

`seed.cmd` / `seed_data.py` دیتابیس را پاک و از نو پر می‌کنند: ۱ مدیر، ۳ کارمند، ۲۰ دانشجو، ۲۰ کتاب و ۲۰ امانت در وضعیت‌های مختلف.
`test.cmd` / `smoke_test.py` هر دو ۲۹ سنجه‌ی یکسان را روی یک دیتابیس موقت اجرا می‌کنند و باید به `ALL TESTS PASSED` برسند.

پس از seed:

| نقش | نام کاربری | رمز عبور |
|-----|------------|----------|
| مدیر | `admin` | `admin123` |
| کارمند | `employee1` / `employee2` / `employee3` | `emp1pass` / `emp2pass` / `emp3pass` |
| دانشجو | مثلاً `ali1` … (در خروجی seed چاپ می‌شوند) | `student123` |

## نقش‌ها و قابلیت‌ها

### دانشجو
- ثبت‌نام در سیستم با انتخاب نام کاربری و رمز عبور (به‌صورت پیش‌فرض فعال است)
- ورود به سیستم
- جستجوی کتاب با ترکیب عنوان / نویسنده / سال نشر و مشاهده وضعیت امانت (موجود یا در امانت)
- ثبت درخواست امانت با بازه زمانی (زمان شروع و پایان)

### کاربر مهمان (بدون ورود)
- مشاهده تعداد دانشجویان ثبت‌نام‌شده
- جستجوی کتاب فقط بر اساس نام (بدون نمایش وضعیت امانت)
- آمار ساده: تعداد دانشجویان، کتاب‌ها، امانت‌ها و آخرین کتاب‌های در امانت

### کارمند کتابخانه (ثبت‌نام کارمند توسط مدیر انجام می‌شود)
- ورود و تغییر رمز عبور
- ثبت اطلاعات کتاب
- جستجو و ویرایش اطلاعات کتاب
- بررسی و تایید/رد درخواست‌های امانتی که تاریخ شروعشان «امروز» یا «دیروز» است
- تحویل کتاب تاییدشده به دانشجو و دریافت کتاب برگشتی با ثبت زمان
- گزارش تاریخچه امانات یک دانشجو + آمار (کل امانات، تحویل‌نشده، با تاخیر)
- فعال/غیرفعال کردن دانشجو (دانشجوی غیرفعال نمی‌تواند امانت بگیرد)

### مدیر کتابخانه
- تعریف کارمند (نام کاربری و رمز عبور)
- گزارش عملکرد کارمند: تعداد کتاب‌های ثبت‌شده، امانت‌های داده‌شده و تحویل‌گرفته‌شده
- آمار امانات: تعداد درخواست‌ها، کل امانت‌های داده‌شده، میانگین روزهای امانت
- آمار همه دانشجویان (مانند گزارش ۳-۶) + ۱۰ دانشجو با بیشترین تاخیر

## مفاهیم وضعیت امانت (Loan)

```
pending  →  approved  →  borrowed  →  returned
    └→ rejected
```

- `pending`: درخواست ثبت شده و منتظر بررسی کارمند است
- `approved`: کارمند تایید کرده؛ دانشجو باید برای تحویل گرفتن مراجعه کند
- `borrowed`: کتاب تحویل دانشجو شده است
- `returned`: کتاب برگردانده شده؛ اگر تاریخ برگشت بعد از پایان بازه امانت باشد، «با تاخیر» است

## نکته‌ها

- درایور `sqlite-jdbc` (لایسنس Apache 2.0) در مخزن نیست؛ `build.cmd` در اولین اجرا آن را از Maven Central داخل `java/lib` دانلود می‌کند. اگر سیستم آفلاین است، فایل `sqlite-jdbc-3.42.0.0.jar` را دستی در همان پوشه بگذارید:
  <https://repo1.maven.org/maven2/org/xerial/sqlite-jdbc/3.42.0.0/sqlite-jdbc-3.42.0.0.jar>
- خروجی خط فرمان هر دو نسخه با ورودی یکسان، بایت‌به‌بایت یکسان است (تست شده روی سناریوهای مهمان، مدیر، کارمند و دانشجو).
